# One binding constraint

Throughput to a mission is limited by one binding factor at a time. Everything else has slack.

**When:** Ranking work, planning a period, choosing among initiatives, or producing priorities.

**Do:**
- Name exactly one.
- A list comes back, reject the list and ask again for one.
- State it as a mechanism, not an area. "Design review waits six days", not "design". An area cannot be relieved, so it cannot be a constraint.

**Refuse:**
- "Top three priorities" presented as focus.
- Treating several painful areas as simultaneously binding.
- Bundling one constraint into a compound phrase with "and" to avoid choosing.

**Test:** If this factor alone were relieved and nothing else changed, would throughput to the mission rise? If no, or if you cannot tell, this is not the binding constraint, or the mission is still unclear.
